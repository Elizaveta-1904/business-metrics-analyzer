# Ответы на контрольные вопросы

## 1. Чем отличается Git от GitHub?

**Git** — распределённая система контроля версий, работает локально на компьютере.
**GitHub** — облачная платформа для хранения Git-репозиториев и совместной работы.

## 2. Для чего используется виртуальное окружение Python?

Для **изоляции зависимостей** разных проектов. Каждый проект получает свои версии библиотек, которые не конфликтуют с другими проектами.

## 3. Что такое commit, branch, remote, pull request?

- **commit** — фиксация изменений в истории проекта.
- **branch** — отдельная ветка разработки.
- **remote** — удалённый репозиторий (например, на GitHub).
- **pull request** — запрос на слияние изменений из одной ветки в другую.

## 4. Зачем нужен файл `.gitignore`?

Чтобы указать файлы и папки, которые Git **не должен** отслеживать: `.venv/`, `__pycache__/`, `.env`, `.idea/`, `.vscode/` и другие.

## 5. Как организовать командную работу над бизнес-приложением с помощью Git?

1. Создать общий репозиторий.
2. Работать в **отдельных ветках** (`feature/...`).
3. Делать **коммиты** с понятными сообщениями.
4. Отправлять изменения через **push**.
5. Создавать **Pull Request** для слияния в `main`.
6. Проводить **код-ревью**.
7. Сливать через **merge**.

## 6. Какие файлы обязательно должны быть в репозитории учебного проекта?

- `README.md` — описание проекта.
- `.gitignore` — исключения для Git.
- `requirements.txt` — зависимости.
- `main.py` — главный файл программы.
- `docs/` — документация (например, `business_requirements.md`).

## 7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?

Возникнет **конфликт слияния** (merge conflict). Git не сможет решить его автоматически — нужно **разрешить вручную**: открыть файл, выбрать нужные строки, удалить маркеры `<<<<<<<`, `=======`, `>>>>>>>`, затем сделать коммит
